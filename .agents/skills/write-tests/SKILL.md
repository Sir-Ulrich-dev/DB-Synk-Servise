# Навык: Написание и обновление тестов (write-tests)

Используйте этот навык всякий раз, когда создаётся или модифицируется сервис, репозиторий или логика синхронизации.

## Принципы тестирования
- **Фреймворки:** JUnit 5 (Jupiter), AssertJ, Mockito.
- **Именование:**
  - Unit-тесты: `*Test.java` (например, `SyncTaskServiceTest.java`)
  - Интеграционные тесты: `*IT.java` (например, `PostgresConnectionIT.java`)
  - Тестовые методы: `should<ExpectedBehavior>When<Condition>()` (например, `shouldThrowExceptionWhenConnectionFails()`).
- **Изоляция:** В unit-тестах все внешние зависимости мокируются (`@ExtendWith(MockitoExtension.class)`, `@Mock`, `@InjectMocks`).
- **Безопасность данных:** Никогда не использовать реальные производственные учетные данные или персональные данные в тестах.

## Пошаговый процесс

### 1. Определение типа теста
- Для чистой бизнес-логики (`service`, `sync`, `domain`): пишите быстрый изолированный unit-тест с Mockito.
- Для проверки SQL и репозиториев (`repository`): используйте легковесный Spring Boot Test (например, с тестовой базой данных или моком DataSource).

### 2. Реализация тестовых сценариев
Обязательно покрывайте:
- Позитивный сценарий (Happy path).
- Граничные случаи (пустые списки, null-значения, нулевой размер батча).
- Обработка исключений и ошибок соединения (проверка ожидаемого типа исключения через `assertThatThrownBy` или `assertThrows`).
- Идемпотентность (повторный запуск операции не должен приводить к дублированию или ошибкам).

### 3. Проверка и верификация
Выполните запуск конкретного теста в терминале:
```bash
./mvnw test -Dtest=<TestClassName>
```
Если тест проверяет конкретный метод:
```bash
./mvnw test -Dtest=<TestClassName>#<methodName>
```

Убедитесь, что линтер не выдаёт замечаний:
```bash
./mvnw checkstyle:check
```
