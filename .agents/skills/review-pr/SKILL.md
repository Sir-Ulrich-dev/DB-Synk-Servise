# Навык: Код-ревью пулл-реквеста (review-pr)

Используйте этот навык по прямой команде пользователя для проверки изменений в ветке перед слиянием в `main`.

## Чек-лист проверки

### 1. Анализ изменений (Diff)
- Получите список изменённых файлов и диффы относительно `main`:
  ```bash
  git diff main...HEAD
  ```
- Проверьте, соответствуют ли изменения заявленной задаче и не содержат ли случайных артефактов (файлы IDE, временные логи, дамп-файлы).

### 2. Безопасность и отсутствие секретов
- Убедитесь, что в коде, тестах и конфигурационных файлах нет жестко закодированных секретов (пароли к БД, токены, приватные ключи).
- Убедитесь в отсутствии неэкранированного SQL (SQL Injection) и опасных DDL-запросов (`DROP`, `ALTER`).

### 3. Архитектура и стандарты проекта
- Соответствие слоям Spring Boot: отсутствие бизнес-логики в `@Repository` и `ui`.
- Внедрение зависимостей через конструкторы (Constructor Injection).
- Корректность именования классов (`*Service`, `*Repository`, `*Config`, `*View`).

### 4. Тесты и линтер
- Проверьте наличие тестов на новую функциональность.
- Запустите сборку и линтер:
  ```bash
  ./mvnw checkstyle:check
  ./mvnw test
  ```

### 5. Формирование отчёта
Предоставьте пользователю структурированный отчёт:
- **Резюме изменений:** краткая суть PR.
- **Положительные стороны:** что сделано хорошо.
- **Замечания и риски (Critical / Warning / Suggestion):** конкретные файлы и строки с рекомендациями по исправлению.
- **Вердикт:** `Готово к слиянию` / `Требуются доработки`.
