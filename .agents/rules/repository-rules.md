# Правила для слоя доступа к данным (Repository / Spring JDBC)

Настоящие правила обязательны при разработке классов в пакете `com.dbsync.repository` и любых компонентов прямого взаимодействия с базами данных (Oracle и PostgreSQL).

## 1. Защита от деструктивных изменений и безопасность
- **Запрет DDL:** Категорически запрещено выполнять `DROP TABLE`, `TRUNCATE TABLE`, `ALTER TABLE` и другие разрушительные операции без явного согласования.
- **Безопасность SQL:** Использовать только параметризованные запросы через `NamedParameterJdbcTemplate` или `JdbcTemplate` с плейсхолдерами `?` / `:param`. Запрещена конкатенация строк в SQL для предотвращения SQL-инъекций.
- **Секреты:** Не логировать значения параметров, содержащие пароли, токены или конфиденциальные данные.

## 2. Идиоматичный Spring JDBC
- Использовать типизированные `RowMapper<T>` или фабричные `DataClassRowMapper` / `BeanPropertyRowMapper`.
- Методы репозиториев должны возвращать `Optional<T>` для одиночных записей и пустые коллекции (`List.of()`) при отсутствии данных (не возвращать `null`).
- Обрабатывать специфичные исключения Spring `DataAccessException` на сервисном уровне, не подавляя их в `catch(Exception e) {}`.

## 3. Батчинг и производительность
- При вставке или обновлении множества записей использовать пакетные операции (`batchUpdate`).
- Учитывать диалекты SQL: для Oracle использовать синтаксис `MERGE INTO`, для PostgreSQL — `INSERT ... ON CONFLICT` при реализации upsert-операций.
